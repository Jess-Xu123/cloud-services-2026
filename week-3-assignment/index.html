Question 1

Describe reasons why so many (most?) companies are using cloud based email and calendar services

Answer:

Cloud-based email and calendar services refer to messaging, scheduling, and contact management tools hosted on remote servers managed by third-party cloud providers, rather than on local physical servers within an organization's building (The HBP Group, 2025; HostDime, 2025)

Instead of purchasing, setting up, and maintaining hardware and software locally, companies access these services on-demand over the internet via web browsers, desktop apps, or mobile applications (The HBP Group, 2025). The cloud vendor takes complete responsibility for server maintenance, security patches, hardware upgrades, data backups, and high-availability infrastructure (HostDime, 2025).

In daily life, almost every enterprise around us replies on these services. For example, global banks, university systems, retail giants, and tech companies using Google Workspace (Gmail and Google Calendar) or Microsoft 365 (Exchange Online and Outlook Calendar) so their thousands of employees can book meetings and communicate globally in real time.

There are noticeable benefits for companies and their customers using cloud-based email and calendar services:

Benefits for companies:

Cost efficiency: Companies reduce heavy upfront expenses on physical servers and storage disks (The HBP Group, 2025). Instead, they transition to a predictable subscription model - paying only per active user, which avoids the financial strain of maintaining expensive on-premises hardware (HostDime, 2025; The HBP Group, 2025).

Scalability and Flexibility: If a company hires 100 new employees tomorrow, admin can provide 100 new cloud email accounts in minutes (HostDime, 2025; Sim Networks, 2019). If the team downsizes, licenses can be removed immediately without leaving unused hardware sitting idle (Sim Networks, 2019; The HBP Group, 2025).

Automatic maintenance and Security:Security fixes, spam filtering, data encryption, and software updates are deployed instantly by cloud providers (HostDime, 2025; Sim Networks, 2019). Internal IT teams are freed from manual patching and server maintenance, allowing them to focus on core business projects (HostDime, 2025; Sim Networks, 2019).

Disaster recovery: Cloud providers store redundant backups across geographically distributed data centers (HostDime, 2025; Sim Networks, 2019). If a local office experiences a power outage pr hardware failure, business operations can continue without data loss or email downtime (HostDime, 2025; Sim Networks, 2019).

Benefits for customers:

Anytime, Anywhere Accessibility: Customers and clients can communicate without gaps, as employees or students can access real-time synchronized emails and schedules from any mobile or desktop devices globally (HostDime, 2025; The HBP Group, 2025).

Question 2

Your thoughts about when to maintain your own web server and when to use SaaS/PaaS/IaaS to provide web services?

Answer:

Before deciding when to maintain my own web server and when to use these web services providers, it would be beneficial to understand the definitions and differences among these web services.

IaaS (Infrastructure as a Service): It provides raw virtualized computing resources (VMs, storage, networking). Users manage the OS, runtime, data, and applications, while the provider manages physical hardware (Red Hat,2026). For example, CSC cPouta is IaaS provider.

IaaS provides the highest level of control, but also requires the most maintenance.It offers flexibility and scalability, but requires more technical knowledge and hands-on work (Google Cloud,2026).

PaaS (Platform as a Service) It offers a cloud environment to build, deploy and manage applications without configuring underlying servers. The provider manages the hardware, OS, and runtime (Google Cloud,2026). For example, CSC Rahti.

PaaS provides a balance between control and maintenance, the user mainly manages their applications. It makes development easier and faster, but gives the user less control and customization.

SaaS (Software as a Service) It delivers ready-to-use, fully managed software over the internet via a web browser (OneAdvanced, 2026).

SaaS provides the least control but requires almost no maintenance. The provider manages everything from infrastructure to the software, and the user simply uses the application. It is easy to set up and use, but offers limited customization and control (Google Cloud,2026).

As a student:

I have used both PaaS with CSC Rahti and IaaS with cPouta. Based on my experience, I think maintaining my own web server is useful when I need full control over the server and want to learn how the infrastructure works. However, it also requires more time and technical knowledge.

For businesses, I think the choice depends on how much control and maintenance is needed. From my experience working for a tech company, we use Slack as a SaaS solution. We can simply use it as a communication tool without having to maintain the software or infrastructure ourselves.

We also use cloud services such as GCP when developing and running our own applications. This gives us more control over our applications and infrastructure while still reducing more of the maintenance work compared to managing everything ourselves.

    Describe reasons, why many IoT devices (internet connected home appliances, Smart-TVs and such) are using Google's 8.8.8.8 or some other public DNS resolvers?

    Answer:

    Many IoT devices use public DNS resolvers such as Google's 8.8.8.8 because they are fast, reliable, and available worldwide (CaptionDNS, 2025). DNS is needed to translate domain names into IP address, allowing IoT devices to communicate with their cloud services (CaptionDNS, 2025).

    Another reason is that public DNS can provide an alternative to local or ISP DNS server. If an ISP's DNS is slow or unavailable, a public resolver such as 8.8.8.8 can still be used. Public DNS services are also free and can save device manufactures from having to operate their own DNS infrastructure (CaptionDNS, 2025).

    Privacy is another consideration when choosing a DNS provider. DNS queries can reveal which domains a device is communicating with. Cloudflare introduced 1.1.1.1 as a privacy-focused DNS service and emphasized limiting the use and retention of user data (Prince, M. 2018).

    Therefore, IoT manufacturers may choose public DNS resolvers because of their reliability, performance, availability, and ease of use, while privacy and security can also influence which DNS provider they choose.
